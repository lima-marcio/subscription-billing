# Philosophy

Baseline rules for new projects under `C:\Prototypes\.net\`. Copy what
applies into the new project's own `.ia/*.md` files, then customize per
project.

- Build production-quality MVPs.
- Finish one complete feature before starting another.
- Reuse existing services, DTOs, validators, components and utilities —
  avoid duplicate code.
- Prefer simplicity (KISS), YAGNI and readable code.
- Organize work by business features, not technical layers.
- Code, identifiers and technical documentation in English.
- Ask for confirmation before creating the top-level `backend/` and
  `frontend/` folders.
- Every project is a Git repository from the start.
